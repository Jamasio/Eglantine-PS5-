# Ocarina of Time (Switch 2) test build 1: what this branch adds

For developers. Test build 1 (build T49) adds 182 core patches and 11 driver patches to viejunerd's v1.219.020 (`88054da`), on core Eglantine `0ca2032`. Claude wrote nearly all of the new code and I tested it on one base PS5 at 12.40. Ocarina of Time 1.1.1 is the only game I tested on it.

The big changes below are off unless `env.txt` sets their switch. Many smaller fixes from earlier builds have no switch of their own and always apply, mostly memory and upload ones, and `sce_sys/param.json` now sets `flexibleMemorySize`. So a build with no `env.txt` still isn't plain v1.219.020. Take what's useful.

Core patches are in `tools/eglantine-patches/`, driver patches in `tools/patch-radv-series/`, and the rest is in `src/`, `headless/` and the scripts in `tools/`. Most patch headers have the reasoning, the source and what was or wasn't run. 47 moved patches only name the patch they came from: `tools/migrate-020.json` lists them, and their `Build gate: EDEN_MIGRATE_020=1` line is a leftover that nothing reads. In the Switch column, (both) means both env files have it, (P) only Prettier, (none) neither.

## Not checked

- Faster has had one run on T49, about 4 minutes. Its 18.7 fps on the scanned stretch isn't understood and may be the route.
- A cold launch on T49 with no shader cache hasn't been run yet. The 4 shader builders may make the title screen and intro slower, and that isn't measured.
- The leaves-on T49 runs weren't the shipped files line for line. All of them had `EDEN_GPU_TIME=1`, and the Handheld run also had `EDEN_NX2_COMPOSE_GUARD=mark` and `EDEN_NX2_MESH_CENSUS=1`.
- The flash numbers are one run each, in Docked, on different routes. Nothing was scanned in Handheld with the two settings. Their fps is the scanner's count of game frames in the recording, not the app's counter.
- Neither flash setting has had a long run. Both have hang reports on Lichii: PR 121 on an RX 9070 XT right after picking the save, PR 337 while loading with only the fence half.
- `tools/check-fence-requirements.py` uses mock classes that weren't updated for `0244-flash-05-query-keep-pending.patch`. My local builds skip that check, so a CI build may stop there.
- Patch headers were written when the patch was. Many say "not run" because they came before the first test.
